S9
Estado persistente del simulador — localStorage🟡 AltaNUEVOSeba🔵 Seba
El simulador pierde todo al cerrar el tab — trades, posiciones abiertas, capital simulado, historial. Antes de Supabase, guardar todo en localStorage con un esquema claro: trades[], openPositions[], capital, journalEntries[]. Es un requisito para que discipline.py y antitilt.py tengan datos reales con qué trabajar entre sesiones.
⚠ Sin esto, discipline y antitilt solo funcionan dentro de una sesión. El usuario pierde su historial cada vez que cierra Chrome.
S10
Indicadores de estado de datos — live / fallback / cargando🟡 AltaNUEVOSeba🔵 Seba
Hoy si Yahoo Finance o allorigins.win fallan, el dashboard no actualiza y el usuario no sabe por qué. Implementar 3 estados visuales en cada KPI: 🟢 dato en vivo, 🟡 dato con delay o desde caché, 🔴 fallback hardcoded. Un punto de color pequeño en cada KPI es suficiente. También un banner global si todas las APIs están caídas.
S11
Tests automáticos de market.js — suite de regresión🟢 MediaNUEVOSeba🔵 Seba
test_apis.html ya prueba las APIs en vivo. Falta una suite de tests unitarios para los cálculos: RSI de una serie conocida debe dar X, MACD de otra serie debe dar Y, MatchingEngine.costos(8420, 100, "buy") debe dar exactamente Z. Si alguien modifica market.js y rompe un cálculo, los tests lo detectan al instante. Sin librería externa — JS puro en un nuevo archivo test_unit.html.
S12
Proxy seguro para Claude API — proteger la API key🟢 MediaNUEVOSeba🔵 Seba
El ítem 18 (Quant-Copilot) usa Claude API. Si la key va directo en el JS del cliente, cualquiera que abra el inspector del navegador la ve y la roba. Necesitan un proxy mínimo: un Cloudflare Worker gratuito que recibe la petición del frontend, agrega la key en el servidor, y la manda a Anthropic. El frontend nunca ve la key real. Hacer antes de activar el Quant-Copilot.
⚠ Sin esto no pueden publicar el Quant-Copilot. La key expuesta en producción se agota en horas si alguien la encuentra.
